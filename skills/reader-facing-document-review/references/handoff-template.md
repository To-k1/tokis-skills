# 审稿第二阶段｜事实与意图交接提纲

**这不是发给用户填写的表，也不能用于第一阶段冷读。** 产品经理应从用户原话、源代码、测试记录、文件等提取已有信息；对未知项写“未提供/待核实”。不让工程 Agent 的自我评价充当作者意图。

- **第一阶段结果的原文与来源**：审稿者已独立读到什么、记录了什么；不要事后重写成产品经理希望它说的话。
- **作品目的与读者**：用户明示内容、读者实际使用场景、尚属推测的方面分别标明。
- **希望读者形成的理解**：强调哪些真实贡献和成果，及其必要的比较、示例和判断条件；不要写成必须提某几个词。
- **事实材料与来源**：实际使用的技术、关键版本、项目自己完成的工作；设计意图、已实现功能、验证结果、真实部署及规划的明确边界。说明材料中的时间/版本冲突。
- **项目和表达限制**：必须保留的事实、演示材料的可用性、现有长度/形式、何处有需要特别警惕的错位。
- **材料路径**：最终读者接触的成稿、实际版式（若有）、原始证据、可比较的过往版本；说明哪些实际上不可读。
- **需要作者决定的取舍**：只记录确实影响成果定位或对外承诺的问题及目前理由；不要要求审稿者替产品经理作决策。

对照阶段不要求审稿者同意产品经理，也不应默认第一阶段的印象就永远正确。鼓励它在事实支持时更新阅读判断，并解释为什么。
