# Skill 审查与验收

每项 skill 分别检查安装结构和实际行为。

## 结构

`node bin/tokis-skills.js review <name>` 或 `npm run validate` 检查目录名、单行 `name`/`description`、本地 Markdown 链接与附带 Agent 的必填字段。引用资源应随 skill 安装后仍可读。新增草稿需要写完正文；命令通过不等于草稿可用。

附带 TOML 的完整语法应由 Codex 加载验证，或使用标准 TOML 解析器检查。CLI 只检查声明字段与文件存在性。

## 行为

用真实或合成任务检查：

- 一个明确应该触发的任务，确认描述能路由到该 skill。
- 一个相邻但不适用的任务，确认没有抢占其他工作。
- 一个信息不全的任务，确认它利用已有材料，并只询问影响结果的未知项。
- 一个已有结果可直接交付的任务，确认不会制造无关修改。

观察实际输出和工具行为，记录重要偏差、证据和必要修正。不要只按是否命中关键词给分。未提供的事实不能变成成果，未发生的独立线程不能写成“已独立审稿”。

## 本次导入的展示型文档 skills

角色入口、引用章程与合成试用材料保留原样。产品经理是主 Agent 的角色；审稿人是独立第二读者，并按先冷读、再对照证据的两阶段方式工作。产品经理的 grilling 外部依赖没有捆绑在仓库中。

可以用 `skills/technical-deliverable-product-manager/tests/` 中的样例进行真实 Codex 试用；这些虚构事实不能进入当前项目的成果介绍。当前仓库的 CLI 测试只验证安装与更新流程，尚不证明角色已在真实模型会话中端到端运行成功。
